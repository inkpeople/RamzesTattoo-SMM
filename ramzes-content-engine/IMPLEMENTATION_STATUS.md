# RAMZES AI — статус реализации

Ветка: `ramzes-ai-orchestrator-implementation`
PR: https://github.com/inkpeople/RamzesTattoo-SMM/pull/7

## Этап 1 — реестр и маршрутизация

- Реестр содержит 37 уникальных специализаций со стабильными ID.
- Детерминированный планировщик выбирает тип задачи и ограниченный состав команды без LLM-вызова.
- Контентный pipeline возвращает выбранный план и адаптирует результат под явно названные площадки.
- Исследовательский сценарий подключён к `run_specialist_team`.
- Шесть детерминированных инструментов: оценка заявки, экономика скидки, поиск повторов, аудит метрик, preflight публикации и расчёт воронки.

## Этап 2 — аналитика, память, открытые источники и отчёты

### Реализовано в коде

- Команды владельца: `/lead`, `/leadstage`, `/booking`, `/publication`, `/metric`, `/memory`, `/analytics`.
- Заявки сохраняются со структурированными полями и объяснимой оценкой приоритета.
- Записи могут ссылаться на `lead_id`; конверсия заявки в запись рассчитывается только при явной связи.
- Метрики публикаций могут ссылаться на `publication_id`; аналитика рассчитывает вовлечённость только при наличии просмотров и сравнивает связанные публикации.
- Добавлены таблицы для заявок, записей, публикаций, событий долгосрочной памяти, открытых рыночных источников и истории запусков агентов.
- Подтверждённые события памяти добавляются в контекст новых задач.
- Маршрутизатор расширен для аналитики, продаж, воронки, репутации, рефералов, кампаний, портфолио и других ролей.
- Конкурентный и трендовый мониторинг использует доступные публичные поисковые источники: Brave Search при наличии ключа, иначе RSS fallback. Источники дедуплицируются и сохраняются в SQLite-кэше и/или выделенной базе.
- Добавлен GitHub Actions workflow для ежедневного мониторинга и бизнес-сводки в Telegram в 06:00 по Новосибирску. Он не отправляет сообщения на обычных push-событиях; рабочие шаги запускаются по расписанию или вручную.

### Проверки

- Python compileall и unit/security tests запускаются GitHub Actions на каждом коммите.
- Проверки маршрутизации, расчётов, парсеров и публикационной аналитики добавлены в тестовый набор.
- Последний успешный запуск нужно смотреть по текущему SHA ветки: https://github.com/inkpeople/RamzesTattoo-SMM/actions

### Что пока не подключено к живым данным

- В репозитории нет подтверждённого API/webhook-коннектора к Tattoo Manager. Команды `/lead` и `/booking` сейчас принимают ручной ввод владельца; автоматическая синхронизация с календарём не заявляется.
- Закрытая статистика Threads, VK и Instagram не подтягивается автоматически. Метрики добавляются вручную через `/metric`; открытые источники не дают достоверных закрытых охватов и бюджетов.
- Миграции второго этапа добавлены в GitHub, но не применены: отдельный проект RAMZES AI ещё нужно создать/подключить, выполнить миграции и проверить Data API/RLS.
- Ежедневный бизнес-отчёт требует `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `TELEGRAM_BOT_TOKEN` и `TELEGRAM_OWNER_ID` в GitHub Actions Secrets. Секреты в код и чат не добавлялись.
- Расписание GitHub Actions начнёт работать автоматически только после попадания workflow в default branch. До этого можно использовать ручной запуск после настройки секретов.
- Полная автоматизация маркетинговых публикаций, исходящих сообщений, рекламных кампаний и контакта с лидами не включена; такие действия не выполняются без отдельного разрешения владельца.

## Безопасность и границы изменений

- PR остаётся Draft и не объединён в production.
- Render, текущий Telegram webhook и токен работающего бота не менялись.
- Новые платные сервисы и проекты не создавались.
- Supabase migration содержит RLS и grants только для `service_role`; таблицы не открываются `anon` или `authenticated`.
- Подробная инструкция активации: `STAGE2_SETUP.md`.
