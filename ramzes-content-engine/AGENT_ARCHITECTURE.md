# RAMZES AI — автономная агентная архитектура

## Принцип

RAMZES AI — одна система с общей памятью, но с отдельными специализированными ролями. Агенты передают друг другу результат, а не генерируют пять несвязанных ответов.

## Команда

1. **Исследователь рынка** — открытые источники, конкуренты, предложения, поисковые темы, ссылки и пробелы данных.
2. **Стратег** — цель, аудитория, позиционирование, гипотеза, формат, CTA и критерии результата.
3. **Копирайтер** — оригинальный материал по брифу стратега.
4. **Редактор** — стиль RAMZES, структура, ясность, адаптация под площадку и устранение повторов.
5. **Аналитик** — проверка фактов, соответствия задаче, качества и результатов публикаций.

В первой реализации роли исследователя и стратега/копирайтера выделены в отдельный модуль `agents.py`. Существующие этапы редактора и независимой проверки в `app.py` сохраняются как отдельные роли. Это уменьшает риск регрессии текущего бота.

## Общая память

Использовать существующие серверные таблицы:
- `ramzes_content_engine_brand_profile` — подтверждённые факты, голос бренда, аудитория, ограничения.
- `ramzes_content_engine_content_library` — черновики и публикации, площадка, тема, хук и статус.
- `ramzes_content_engine_metrics` — просмотры, реакции, переходы, заявки, записи и рекламные расходы.
- `ramzes_content_engine_chat_history` — контекст диалога.

Новая постоянная память должна быть включена только после создания отдельного проекта Supabase, применения миграции и проверки чтения/записи. До этого система честно сообщает о временном режиме и не обещает сохранность между перезапусками.

## Контент-завод

Единый исходный бриф → отдельные версии Threads, VK, Instagram и Telegram. Не копировать один и тот же текст между площадками: адаптировать длину, хук, ритм, CTA и формат.

## Автономный цикл

1. Плановый запуск GitHub Actions собирает публичные сигналы рынка.
2. Исследователь готовит источники и ограничения данных.
3. Стратег выбирает возможности и формирует бриф.
4. Копирайтер создаёт варианты под площадки.
5. Редактор и аналитик проверяют материалы.
6. Отчёт с идеями и приоритетами отправляется в Telegram.
7. После получения реальных метрик аналитик сравнивает результаты и обновляет рекомендации.

## Ограничения

- Не заявлять о доступе к закрытой статистике Threads/Instagram/VK.
- Не придумывать охваты, бюджеты, цены, рейтинги и результаты конкурентов.
- Публикация от имени RAMZES и запуск платной рекламы требуют отдельного разрешения владельца.
- Планировщик GitHub Actions — периодический, не 24/7.
- GitHub Actions Cache не является долгосрочной базой данных.
- Не менять существующий Telegram webhook в рамках этой архитектурной ветки.

## Этапы внедрения

1. Ролевой pipeline и тесты.
2. Подключение к текущему обработчику Telegram без изменения webhook.
3. Постоянная память Supabase и миграция.
4. Адаптеры платформ и аналитические отчёты.
5. Планировщик и автономные ежедневные отчёты.
